# QDM 开发指南（0.2.1）

## 已实现范围

这是可编译运行的 HTTP/HTTPS 下载 MVP，Qt 固定 5.8.0 / msvc2013_64。已实现任务表、队列、筛选、托盘、单实例、暂停恢复、SQLite 状态保存、Range 探测和分段、单流回退、重试、检查点摘要及发布恢复。

现阶段一个任务活跃，其他任务排队；单任务配置 1～64 路并发，最小分段约 8 MiB，小文件会降低实际并发。任务可以在运行中添加、暂停、恢复、移除。移除会清理专属临时文件，保留最终输出。主窗口关闭后隐藏到托盘，Ctrl+Q 或托盘菜单可以明确退出并保存。

浏览器扩展已实现资源识别、页面扫描、右键下载、Native Messaging 和便携配对，安装见 `browser-extension/README.md`，设计见 `docs/浏览器扩展设计.md`。视频站点解析、HuggingFace 清单、全局限速及多任务公平调度尚未实现。README 描述的是完整目标，本文件描述当前源码行为。

## 构建与运行

本机已验证工具链：

```text
Qt       D:\Qt\Qt5.8.0\5.8\msvc2013_64
VC       D:\Program Files (x86)\Microsoft Visual Studio 12.0\VC
Compiler MSVC 18.00.21005，x64
```

依赖已放在 third_party。新检出缺少依赖时先执行 `python scripts/bootstrap.py`，脚本从官方源获取固定包并验证摘要。然后在仓库根目录执行：

```powershell
.\scripts\build.cmd
.\build\release\bin\QDM.exe
```

当前只维护 `build/release/bin` 一个运行版本。baseline/debug/optimized 等重复构建已经清理，脚本不再接受其他版本参数，qmake 也关闭了默认 Debug/Release 双配置生成。编译前通过 Ctrl+Q 保存退出正在运行的 QDM，避免 EXE 被占用。

0.1.2 已将 release 与 optimized 两处程序同步更新，并在窗口标题、状态栏及 Windows 文件版本中显示版本。启动后写入 runtime.json（仅 PID、版本、程序路径），重复启动时结合实例锁 PID 校验元信息：同一程序唤回窗口；版本未知、不同版本或不同路径则明确提示“版本未切换”，不会强制终止原实例。正常退出清理其元信息，异常遗留文件不会仅凭内容被信任。

0.2.0 构建还会生成同目录的 QDM.NativeHost.exe。浏览器桥只监听 127.0.0.1:17878，GUI 的“浏览器扩展”窗口设置默认目录、并发及复制便携配对信息。首次打开旧数据库时，先用 SQLite backup API 保存 tasks.sqlite.pre-v2.bak，再迁移到 schema v2；旧版不能降级写入 v2 数据库。

单实例回归使用 `python tests/instance.py`，在隔离数据目录验证元信息、重复启动拒绝、原进程保持运行和正常退出的检查点保存。升级时必须通过 Ctrl+Q 或托盘“退出并保存任务”结束旧实例，关闭窗口默认只是隐藏。

构建脚本负责 qmake/nmake 构建、浏览器宿主及部署。QDM.pro 已包含链接前生成 curl C ABI 导入库的步骤，Qt Creator、nmake 和 VS2013 都无需手工复制 curl-import.lib；构建后自动复制 curl DLL 并运行 windeployqt。

### VS2013 构建

使用 VS2013 打开仓库根目录的 `QDM.sln`，选择 `Release | x64` 后重新生成。当前工程使用本机 `D:\Qt\Qt5.8.0\5.8\msvc2013_64`，输出为 `bin\QDM.exe`。浏览器宿主仍由 `scripts\build.cmd` 构建。

`LNK1181: 无法打开输入文件 curl-import.lib` 的原因是旧工程只配置了库路径，没有执行脚本中的导入库生成步骤。现在工程的“生成事件 → 预链接事件”会使用 VS2013 的 `lib.exe`，从随附的 `libcurl-x64.def` 生成当前构建目录的 x64 导入库。修改构建配置应同时修改 QDM.pro，避免重新导入 Qt 工程时丢失修复。

本项目没有 NuGet 程序包依赖。日志中的 `NuGet.VisualStudio.VsUtility.GetNuGetSolutionFolder` 路径异常与上述链接错误分开处理：先关闭临时解决方案，打开已保存的 `QDM.sln` 后重试。若仍报错，需要检查 VS2013 的 NuGet 扩展及解决方案路径；命令行 MSBuild 验证不覆盖 IDE 内 NuGet 扩展行为。

`CONFIG += no_batch` 是此机器 v120 编译器的兼容设置：已观察到多源批编译反复报 D8000，单文件编译正常。不要在没有验证的情况下删除。Qt 主程序及 SQLite 用 v120 编译；libcurl 使用官方 x64 C DLL，未跨 DLL 传递 Qt/STL/C++ 异常。

中文 `.cpp` 使用 UTF-8 BOM 与 `#pragma execution_character_set("utf-8")`。只有 BOM 仍可能让 v120 将窄字符串编码为系统代码页，导致 `QString::fromUtf8` 乱码。代码格式由根目录 `.clang-format` 管理。

## 数据与恢复

- 默认数据目录：Windows 当前用户 AppLocalDataLocation/QDM 对应目录；可使用 `--data-dir` 指定。
- 在程序目录添加 `portable.flag` 后使用同目录 data 文件夹；不会自动导入其他位置的数据。
- 文件下载到最终目录内的 `<文件名>.qdm-<UUID>.part`，完成后同卷重命名；不覆盖已存在目标。
- 运行中的 received 是实时写入数，committed 才是 SQLite 已确认可恢复数。
- 每约 2 秒及暂停/退出/完成时：QFile flush → FlushFileBuffers → SHA-256 检查点 → SQLite 单语句原子保存。
- SQLite 使用 WAL/FULL，保存任务时 URL 用当前用户 DPAPI 加密。便携数据不保证跨机器解密；不要在运行中只复制主数据库作为备份。
- 恢复先重新探测资源身份，再校验临时文件的已提交区间摘要。资源变化或检查点损坏时从零重下；不把未校验字节拼入结果。
- 没有强 ETag 或 Last-Modified 的资源不复用旧字节。没有 Range 支持的任务暂停后恢复会重新下载。
- 首期完成时做长度与传输覆盖检查；本地检查点摘要用于恢复完整性，不能代替来自服务器的可信全文件摘要。

## 源码阅读路径

1. `src/main.cpp`：参数、单实例、工作线程、退出屏障。
2. `src/task.h/.cpp`：快照、半开区间、64 位偏移序列化。
3. `src/downloadengine.h/.cpp`：调度、探测、响应校验、传输、检查点、暂停恢复。
4. `src/repository.h/.cpp`：SQLite C API、绑定参数、DPAPI 地址保护、schema 版本。
5. `src/mainwindow.h/.cpp`：QAbstractTableModel、筛选、表单、托盘及异步命令。
6. `tests/integration.py`：真实 EXE、可控 HTTP 服务和故障恢复验证。

所有下载对象、文件、数据库都归工作线程。UI 通过 queued signals/slots 发命令并接收 Task 值快照。libcurl 回调内只校验头、写入当前有界数据块及更新哈希，不销毁 handle；pump 在 socket_action 返回后处理完成消息并统一清理。

0.1.1 使用 libcurl socket/timer 回调 + Qt 5.8 QSocketNotifier 驱动网络，取消固定 20 ms 轮询。100 ms 心跳只维护重试、UI 和检查点，不决定网络接收频率。Windows SOCKET 是指针宽度，而 Qt 5.8 activated 信号使用 int，因此 lambda 捕获原始 socket，不能从信号参数重建它。监视器删除先禁用、断连再 deleteLater；socket 数值复用由 serial 防止迟到事件误用。libcurl timeout=0 经单次 QTimer 异步执行，禁止在回调里递归调用 libcurl。

公共接口和文件头说明职责与线程，关键逻辑解释 Range 闭区间转换、200 回退、代次替代机制、文件先于 DB 提交、最终发布恢复。后续新增接口仍需遵循《技术方案》第 12 节。

## 与最终架构的差异

当前引擎将 Scheduler、FileWriter 和 Repository 串行放在单个工作线程，文件同步写入直接消耗 libcurl 单次回调块，不创建无界缓冲队列。其优点是生命周期和检查点顺序直观；慢磁盘写入、刷盘和大型恢复校验会延迟工作线程处理暂停等命令。GUI 不会同步等待这些工作，明确退出会等待保存完成。

此模型中移除 easy handle 后不会再收到它的网络回调，且所有命令串行，因此尚未引入独立 generation 字段。拆分写线程/数据库线程、引入延迟完成事件时，必须同时引入 generation、队列反压和取消屏障，不能只把 QFile 移到另一个线程。

目前任务和段使用一个 JSON 字段原子保存，偏移以十进制字符串避免 JSON double 精度丢失。最终多任务版本再迁移为独立段/检查点表；迁移时增加 schema 版本并补充兼容测试。

官方 libcurl Windows 包的实际 TLS 后端为 LibreSSL，并非方案优先选择的 Schannel。当前显式开启系统 CA，保留证书链/主机名验证，已经验证实际 HTTPS 下载。版本、来源和构建选项见 dependencies.lock；后续若自行构建 Schannel 后端，需重新验证 ABI 与证书行为。

首期不支持自定义认证请求头、代理设置界面、长路径承诺、文件稀疏/预分配、自动修复全部下载失败。超过 4 GiB 文件的类型和偏移采用 64 位，但该规模尚未完成实测，不能据此宣称验收通过。Qt Test、稳定性压测和干净 Windows 安装包验证仍属后续工作。

## 自动化验证

需要 Python 3.11 或更高版本，仅使用标准库：

```powershell
python tests\integration.py
```

使用唯一 Release 构建运行回归和 TLS 吞吐诊断（TLS 脚本还需要 openssl）：

```powershell
$env:QDM_EXE = 'D:\project\QDM\build\release\bin\QDM.exe'
python tests\integration.py
python tests\benchmark.py --exe build\release\bin\QDM.exe --tls
python tests\benchmark.py --exe build\release\bin\QDM.exe --tls --complete --size-mib 512 --connections 4,64 --check-untrusted
```

benchmark 在隔离目录生成短期测试证书，以 `--ca-file` 显式传入，不修改系统证书、不关闭校验。完整模式验证最终 SHA-256；`--check-untrusted` 验证不传测试 CA 时连接仍会被拒绝。性能结果是本机诊断数据，不代表公网 CDN 保证，详见《性能优化记录》。

测试服务仅监听随机本机端口；每轮生成独立 tests/work/<id>，避免覆盖已有测试文件。断点、崩溃和损坏恢复测试均对最终文件做 SHA-256 对比。强制终止仅针对测试脚本自己创建的 QDM 子进程。

CLI 同一引擎可用于诊断：

```powershell
.\build\release\bin\QDM.exe --headless --url 'https://example.com/file.zip' --output 'D:\download\file.zip' --connections 4 --data-dir '.\build\diagnostics'
.\build\release\bin\QDM.exe --headless --resume '<任务UUID>' --data-dir '.\build\diagnostics'
```

stdout 为 JSON 行事件，stderr 为初始化/命令错误。退出码：0 成功或计划暂停，1 下载失败，2 参数/初始化/持久化问题，3 相同数据目录已有实例。`--pause-after <毫秒>` 用于有序退出检查点诊断；不等同于系统断电。
